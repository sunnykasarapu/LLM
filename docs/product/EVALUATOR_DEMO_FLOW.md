# EVALUATOR DEMO FLOW
## LLM Red-Teaming & Safety Evaluation Framework

---

# 1. DOCUMENT PURPOSE

This document defines the structured demo flow for evaluators assessing the platform.

It ensures:
- smooth presentation during evaluation
- clear storytelling of system capabilities
- step-by-step demonstration sequence
- predictable demo outcomes
- high-impact visual and functional walkthrough

---

# 2. PRIMARY OBJECTIVE

The evaluator demo flow exists to:
- showcase end-to-end system capability
- demonstrate safety evaluation intelligence
- highlight attack generation and scoring
- present regression tracking and insights
- ensure strong evaluator impression

---

# 3. DEMO DESIGN PRINCIPLES

---

## 3.1 Story-Driven Flow

Demo must feel like a narrative:
- problem → system → intelligence → insight

---

## 3.2 Controlled Execution Principle

Every demo step must:
- be pre-tested
- be reproducible
- produce stable outputs

---

## 3.3 Visual Impact Principle

Focus on:
- dashboards
- charts
- risk scores
- attack results

---

## 3.4 Time-Bounded Execution

Demo should be completed within:
- 5 to 10 minutes maximum

---

# 4. DEMO PREPARATION CHECKLIST

---

Before starting demo:

- system backend running
- workers active
- synthetic dataset loaded
- mock/live provider configured
- dashboard accessible
- sample evaluation ready
